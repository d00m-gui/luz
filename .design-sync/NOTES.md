# design-sync notes for luz

## Repo-specific gotchas

- **`lui` is a single namespace export, not per-component PascalCase
  exports.** `dist/index.js` exports `luz` + `lui` (`lui.button`,
  `lui.card`, `lui.avatar.root`, ...); `dist/react/index.js` separately
  exports `LuzReact`/`useTheme`. The converter needs individual named
  exports, so `.design-sync/entry.mjs` flattens `lui.*` into `Button`,
  `Card`, `Toggle`, `Avatar`, `Menu`, `Menubar`, `Tabs`, `Meter`, `Form`,
  `Field`, `ToggleGroup`, `Toast`, `Switch`, `Dialog`, plus re-exports
  `LuzReact`/`useTheme` — all from the built `dist/` (never from `src/`,
  keeps the bundle honest to the published package). Build always runs
  `bun run bunup` first (part of `cfg.buildCmd`) so `dist/` is fresh before
  the entry shim imports it.
- **No static CSS ships with the package** — luz is CSS-in-JS: `LuzReact`
  injects `luz(config).style` into a `<style>` tag at runtime. `cssEntry`
  points at `.ds-sync/generated/luz.css`, produced by
  `.design-sync/generate-css.ts` (calls `luz()` + `base()` directly — the
  same two functions `src/astro/index.ts`'s `luzAstro` integration calls in
  its build hook, no Astro build needed). This script is part of
  `cfg.buildCmd` too.
- **Provider config is `luz()`'s own `defaultConfig`** (`{}` — primary
  `#007dea`, dark mode) — the library's out-of-the-box look, not any
  example app's theme. Change `cfg.provider.props.config` to preview a
  different brand.
- **Compound sub-parts are lowercase** (`Dialog.root`, `Menu.trigger`,
  not `.Root`/`.Trigger`) — matches `src/components/types.ts`'s
  `LuiComponents` interface exactly. Conventions.md was corrected once
  already for this (`Dialog.Root` → `Dialog.root`) — verify against
  `src/components/types.ts` before writing similar names elsewhere.
- `examples/` (workspace apps, including `examples/ui` — the only place
  `@base-ui/react` is imported directly rather than through `lui`) is
  intentionally out of scope for the synced bundle — it's demo apps, not
  library source. It IS used as **composition reference** when authoring
  previews (`examples/ui/samples/*.tsx` has the canonical usage pattern per
  component) — read it, never sync it.

## Re-sync risks

- `.ds-sync/generated/luz.css` and `dist/` are both regenerated by
  `cfg.buildCmd` — never hand-edit either, they're overwritten every build.
- The provider's default `LuzConfig` (`{}`) is a literal, not a `$ref` —
  if `luz()`'s own `defaultConfig` (`src/luz.ts`) changes primary/mode, the
  preview look silently shifts on next rebuild without a config diff to
  flag it. Not worth a `$ref` for a 1-line empty object, but worth knowing.
- Only 3/14 components have authored previews — a re-sync's render check
  will keep passing on floor cards for the other 11 by design; don't read
  "render check clean" as "everything is authored".
- `entry.mjs`'s export list is hand-maintained against `LuiComponents`
  (`src/components/types.ts`). If a new top-level `lui.*` key is added to
  that interface, `entry.mjs` needs a matching export line or the new
  component won't be discovered — nothing currently fails loudly if this
  drifts, since the converter just sees fewer exports.
